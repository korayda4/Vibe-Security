## What is Vibe Security?

Vibe Security is the **AI skill** for catching security mistakes in code generated by AI agents (Claude Code, VS Code Anthropic Claude extension, Cursor, Continue.dev).

For every change in a Vibe Coded project, our skill:

1. **Plans** — maps the project's languages and frameworks (React, Next.js, Express, Django, .NET, etc.)
2. **Tests** — runs the scan against 36 rules across 6 layers
3. **Finds** — XSS, SQLi, IDOR, weak hashing, hardcoded secrets, misconfigured CORS, missing security headers, and more
4. **Explains** — every finding has CWE, OWASP, threat model, and step-by-step fix
5. **Fixes** — auto-patch for the most common mistakes (FE-001 DOMPurify, FE-004 source maps, NET-002 CORS)

## Install

### From npm

```bash
npm install -g @korayda4/vibe-security
```

### From GitHub (pre-publish or alternative channel)

```bash
npx -y github:korayda4/Vibe-Security init
```

### MCP server config

**Claude Code** — `~/.claude/mcp_servers.json`:
```json
{
  "mcpServers": {
    "vibe-security": { "command": "vibe-security" }
  }
}
```

**VS Code Anthropic Claude extension** — `.vscode/settings.json`:
```json
{
  "mcp.servers": {
    "vibe-security": { "command": "vibe-security", "type": "stdio" }
  }
}
```

After install, restart your editor. The `/securityCheck` slash command will be available.

## Use

```
/securityCheck                  full project scan, writes Security.md
/securityCheck --frontend       only frontend layer
/securityCheck --fix            preview + apply auto-fixes
/securityCheck --baseline       only NEW findings vs baseline
/securityCheck --rule BE-004    single rule
```

Or talk to Claude naturally:

> "Run a security scan on this project."
> "Any IDOR or SQL injection in the backend?"
> "Explain FE-001 in detail."

## Languages & Frameworks

### Frontend technologies

React · Next.js · Vue.js · AngularJS · Svelte

Vibe Security scans every Frontend angle:

- XSS in `innerHTML` / `dangerouslySetInnerHTML` / `<%= raw %>` / `unsafe { + }`
- Cookie flags (HttpOnly, Secure, SameSite)
- Public env leaks (`NEXT_PUBLIC_*`, `REACT_APP_*`)
- Source maps in production
- Clickjacking protection
- `eval` / `Function` / `setTimeout(string)` misuse
- CSP / HSTS / X-Content-Type-Options / Referrer-Policy / Permissions-Policy

### Backend technologies

Node.js · Express · Fastify · NestJS · Django · Flask · FastAPI · Rails · Sinatra · Laravel · Symfony · WordPress · Spring · ASP.NET Core · Blazor · Actix · Axum · Gin · Fiber · C/C++

Vibe Security scans every Backend angle:

- IDOR / BOLA — ownership not verified
- SQL / NoSQL injection (string concatenation, f-string, `format!`)
- JWT `alg: none`, weak secret, missing expiry
- Mass assignment — input not whitelisted
- Weak password hashing (MD5 / SHA-1 / SHA-256)
- Token in URL query/path
- Long-lived tokens without expiry
- Missing rate limiting on auth endpoints
- Unsafe file upload (original filename used)
- Hardcoded secrets / API keys / AWS keys

### Detection sources

`package.json`, `composer.json`, `Gemfile`, `requirements.txt`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `*.csproj`, `*.sln`, `CMakeLists.txt`. Smart detection via file extension, shebang (`#!/usr/bin/env python3`), and syntax sniffing.

## How it works in a Vibe Coded project

```
User writes code with Claude
    │
    ▼
AI invokes /securityCheck  ──►  Vibe Security MCP server
    │
    ▼
1. PLAN  — detect languages, frameworks, project profile
    │
    ▼
2. TEST  — apply 36 rules across 6 layers (Frontend, Backend,
          Network, Database, CI/CD, Observability)
    │
    ▼
3. FIND  — 36 known vulnerability patterns
    │
    ▼
4. EXPLAIN — CWE + OWASP + threat model + remediation steps
    │
    ▼
5. FIX  — auto-patch for 3 rules; guidance for the rest
    │
    ▼
Security.md written to your project root (not in this repo)
```

## Output

| Format | Use |
|---|---|
| `markdown` | Default `Security.md` in your project root |
| `sarif` | GitHub Code Scanning integration |
| `json` | Programmatic / CI |
| `junit` | Jenkins, GitLab CI |
| `compact` | PR comment summary |

**Important:** `Security.md` is generated at runtime in YOUR project. It is not part of this repo and is gitignored by default. Sample structure: [`docs/SECURITY_REPORT.example.md`](docs/SECURITY_REPORT.example.md).

## Configuration

`.vibe-security.json`:

```json
{
  "rules": { "FE-006": { "enabled": false } },
  "ignore": ["**/vendor/**"],
  "output": { "format": "sarif" }
```

## CI/CD

```yaml
- run: npx -y @korayda4/vibe-security scan . --format sarif --output vibe-security.sarif
- uses: github/codeql-action/upload-sarif@v3
  with: { sarif_file: vibe-security.sarif }
```

Baseline for PR-only-new-findings:

```bash
vibe-security scan . --update-baseline --no-fail    # main branch
vibe-security scan . --baseline .vibe-security-baseline.json    # PR branch
```

Full GitHub Actions: [`examples/github-actions.yml`](examples/github-actions.yml).
